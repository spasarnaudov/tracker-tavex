# imot.bg Scraper (Step 1: data collection only)

Скрипт, който събира обяви за апартаменти от [imot.bg](https://www.imot.bg)
по зададени филтри (град, брой стаи/тип, година на строеж) и ги записва
локално като JSON или CSV.

Това е отделен, самостоятелен проект — не се вписва в структурата на
основния portfolio-tracker (Flask/Android/iOS/PostgreSQL) в останалата
част от това repo. За момента скриптът само събира данни; запис в
PostgreSQL е следваща стъпка.

## Как работи

Резултатите от търсенето на imot.bg се рендерират сървърно (проверено чрез
директна инспекция в браузър — виж `imot-bg-research.md`), затова скриптът
използва само `requests` + `BeautifulSoup`, без браузър автоматизация.
Всички нужни полета (цена, град, квартал, площ, година на строеж, линк) се
виждат директно в списъка с резултати, затова скриптът не влиза във всяка
отделна обява — това пази броя заявки към сайта нисък.

`robots.txt` на imot.bg е изцяло отворен (`Disallow:` е празен, само
`Sitemap:` е зададен) — проверено на 2026-08-24, виж `imot-bg-research.md`.

Скриптът разпознава и пропуска промотираните карти "Жилищна сграда"
(строителни проекти, не единични обяви) — те имат различен формат на ID.

## Изисквания

- Python 3.11+
- Ubuntu или macOS

## Инсталация

**Ubuntu:**

```bash
cd imot_scraper
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Ако `python3 -m venv` липсва: `sudo apt install python3-venv`.

**macOS:**

```bash
cd imot_scraper
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Ако `python3` липсва или е твърде стар: `brew install python@3.12`.

## Конфигурация

```bash
cp config.yaml.example config.yaml
```

Отвори `config.yaml` и задай филтрите си (град, тип/стаи, година на
строеж, макс. цена и т.н.). Всяко поле в примерния файл е коментирано
с това дали стойността е реално проверена на сайта, или е предположение
по аналогия — провери сам на imot.bg преди да разчиташ на непотвърдените
стойности (напр. `type_slug` за 3+ стаи, други `ybuild_type` кодове).

## Стартиране

```bash
source .venv/bin/activate
python scraper.py --config config.yaml
```

По избор:

```bash
python scraper.py --config config.yaml --output listings.csv --format csv
```

Скриптът извежда в конзолата кратко резюме: брой заявени страници, брой
намерени карти, брой пропуснати "Жилищна сграда" карти, брой грешки при
парсване, и колко обяви са събрани общо.

## Изходни данни

Всеки запис в JSON/CSV изхода съдържа:

| Поле | Описание |
|---|---|
| `source_id` | Уникален идентификатор на обявата, извлечен от URL-а |
| `url` | Пълен линк към обявата |
| `title` | Заглавие, напр. "Продава 1-СТАЕН" |
| `property_type` | От филтъра в `config.yaml` (напр. `apartament`) |
| `rooms` | От филтъра в `config.yaml` |
| `city` | Град, парснат от локацията в картата |
| `neighborhood` | Квартал/район, ако е наличен |
| `price` | Цена като низ (за да не се губи прецизност) |
| `currency` | `EUR` или `BGN` |
| `area_sqm` | Площ в кв.м като низ |
| `price_per_sqm` | Изчислено: `price / area_sqm` |
| `year_built` | Година на строителство/въвеждане в експлоатация, ако е разпозната |
| `scraped_at` | UTC timestamp на събирането |

Цена и площ се пазят като низове (не `float`), за да няма закръгляне —
при по-нататъшна обработка ги конвертирай към `Decimal`/`NUMERIC`.

## Етично scrape-ване

- Delay от 2–3.5 сек. между заявките за страници, с лек randomize.
- Реалистичен `User-Agent` (настройваем в `config.yaml`).
- При грешка (timeout, връзка, 5xx) — до 3 опита с exponential backoff.
- При `429 Too Many Requests` — изчаква `Retry-After` (ако е зададен) или
  нараства backoff-а.
- Ако дадена страница не може да бъде взета след всички опити, скриптът
  спира пагинацията и извежда каквото е събрал дотук, вместо да гръмне.
- Грешка при парсване на отделна карта се логва и се пропуска —
  не спира целия скрипт.

## Известни ограничения

- Проверено само за `transaction_type: prodazhbi` (продажби) и град
  София; `naemi` (наеми) и други градове би трябвало да следват същия
  URL модел, но не са тествани.
- `type_slug` е потвърден само за `ednostaen`/`dvustaen`; стойностите за
  3+ стаи в `config.yaml.example` са предположение по аналогия.
- `ybuild_type` кодовете извън `2~3~` не са потвърдени.
- `year_built` се разпознава чрез евристика (първата 4-цифрена година
  1900–2099 в свободния текст на картата) — при нетипичен текст може да
  липсва или рядко да хване грешно число.

## Следваща стъпка

Запис в PostgreSQL (`listings` + `price_history`, upsert логика,
маркиране на изчезнали обяви като неактивни) и cron автоматизация не са
включени в тази стъпка — ще бъдат добавени отделно.
